# SwarmAlpha 项目说明（教授版）：证据披露方向能否纠正多 Agent 的错误共识

---

> 本文档基于**已冻结论文**（`paper.en.md` / `main.tex`，DeepSeek 双 seed 结果，2026-08-17 定稿）整理。所有陈述按项目推理协议标注证据级别：**FACT**（实验/代码/文献直接支持）、**INFERENCE**（合理推导）、**HYPOTHESIS**（待检验命题）、**DESIGN INTENT**（设计意图）、**SPECULATION**（推测）。论文已冻结：本文档不新增科学主张、不改任何数字。

> **一句话总纲**：我们已经证明——多 Agent 走偏后，控制"哪些证据进入公共讨论"确实能改善结果；但还没解决——不知道正确答案时，系统怎么判断"什么时候该干预"。

**主线**：我们研究什么问题（§1）→ 前人怎么做（§2）→ 我们的不同（§3）→ 理论机制（§4）→ 如何验证（§5）→ 目前得到什么（§6）。技术细节与观测点索引见附录 A、B。

## 1. 我们研究什么问题

**问题**：多个 LLM Agent 各自只掌握一部分信息、共同回答一个问题时，讨论往往不能把分散的信息整合起来——群体会**过早地锁定一个自信的错误答案，然后越讨论越坚信它**。

**为什么值得研究**：这是"分布式信息条件下的集体推理失败"。人类群体在同样条件下也会失败（Stasser & Titus 1985 的经典 hidden-profile 结果：每个成员只握有部分事实、没人看到全貌，讨论偏向共享信息、忽略独有信息）；LLM 版本同样失败（HiddenBench：其协议下多 Agent 准确率仅 23–30%；我们的 CONTROL 臂在自有协议下为 63%，口径不同、不可直接比）。

**核心目标**：提高**最终决策的正确性**（用离线正确答案评估），而不是提高一致性——因为"全体一致"可能恰恰是"全体一致地错"。

## 2. 前人怎么做

- **描述这个失败**：Stasser & Titus（人类群体）、HiddenBench（LLM 群体）——分布式信息下集体推理系统性失败。
- **改善交流**：让 Agent 互相辩论（Multiagent Debate）、把讨论组织成层级议会（CHAL）——改变"是否交流、怎么交流、谁和谁交流"。
- **理解失败机制**：群体朝误导性同伴答案修订（Easier to Mislead）、单点错误沿链条传播（Spark to Fire）、以及"涌现的一致是否可信"的诊断（Emergent Consensus、Counterfactual Graph）。

**一句话总结**：已有工作要么描述失败，要么改变交流的**结构**（是否交流、辩论方式、通信拓扑、聚合方式）；**没有人在"已经产出的证据"这个层面上，把"证据的方向"当作一个可操纵的独立变量**。

## 3. 我们的不同：一个新的独立变量

我们把其他一切条件固定（同一群体、同一轮讨论、同一批已产出的证据），只操纵一个变量：

> **已经产生的证据中，哪个方向的证据进入公共讨论。**

- "支持"方向（`supports`）：证据倾向于支持某个选项；
- "攻击"方向（`attacks`）：证据倾向于挑战某个选项。
（这两个方向标签是模型自己报告的分类，不是外部验证的客观真值——见 §6 边界。）

**为什么这是一个独立且值得研究的问题**：当群体已经锁定了（可能是错的）方向，继续让大家看到"支持当前方向"的证据，和让大家看到"挑战当前方向"的证据，对群体的走向可能有系统性不同的影响。这个问题独立于"是否交流、怎么交流"——即使交流结构完全不变，仅改变"被看见的证据的方向"，也可能改变结果。这是我们与所有已有工作的分界点。

## 4. 理论机制：为什么"方向"可能不对称

这是本文的**研究假设**（代码只是验证它的手段）：

- 群体已经错误锁定时，继续暴露支持当前方向的证据 → **可能强化错误**（加固效应）；
- 暴露挑战当前方向的证据 → **可能打破错误收敛**（纠偏机会）。

为什么不对称：从群体当前的信念出发，"支持"和"攻击"不是对称的——支持只会加固已有立场，而攻击才可能制造翻转的契机。如果群体的当前立场是错误的，那么"只披露支持性证据"的策略会系统地帮倒忙，而"披露证伪性证据"的策略有机会救场。

由此形成两个可检验假设：
- **H1**：证伪性披露 vs 证实性披露——方向本身影响结果（ATTACKS − SUPPORTS 显著为负）。
- **H2**：证伪性披露 vs 不披露（ATTACKS − CONTROL 显著为负）。

## 5. 我们如何验证：identical-state fork

用一个"同状态分叉"实验把方向隔离开：

1. 每个群体先正常进行第一轮讨论（每人报告自己的信念和证据，看不到别人）；
2. 同一个第一轮状态**分成三个组**：
   - **CONTROL**：什么都不额外披露；
   - **SUPPORTS**：只把"支持"类证据放进公共讨论；
   - **ATTACKS**：只把"攻击"类证据放进公共讨论；
3. 三组继续第二轮讨论，最后各自私下给出最终判断；
4. 用离线正确答案给三组的最终判断打分（Brier：衡量概率预测离正确答案多远，越小越好）。

三组的差别**只有披露方向**，因此结果差异归因于方向。

**可信性的两个关键保证**：
- **truth firewall**（运行时不能偷看正确答案）：披露策略在线运行时不看正确答案，正确答案只用于实验结束后的打分——排除"偷偷作弊"；
- **统计身份**：seed 0 = 预注册确认（先冻结假设再看结果）；seed 1 = 事后复现；两 seed 汇总 = 稳健性汇总（不是重新标记的预注册结果）。

（工程细节——证据注册表、状态哈希、路由器等——见附录 A，正文不展开。）

## 6. 目前得到什么

**已建立的（FACT，双 seed，45 任务）**：

1. **方向本身显著影响结果**：证伪性披露整体显著优于证实性披露（H1 pooled −0.412，95% CI [−0.571, −0.267]）与不披露（H2 pooled −0.330，CI [−0.497, −0.188]）；两 seed 方向一致，留一任务稳健（LOTO：28 负 / 7 正 / 10 零）。
2. **效果集中在已经严重走偏的群体**：第一轮就错得很严重的 15 个任务上，证伪披露平均改善 0.79（Brier）；中等任务改善 0.11；一开始就对的任务（n = 2）几乎无变化。群体错得越厉害，证伪披露帮助越大（ρ = −0.60；探索性、事后分析）。
3. **但系统不知道"何时该干预"**：一个不依赖正确答案的失败预测器（证据复用率）在开发集有效（r = 0.388），在确认集不迁移（r = −0.08）。**干预有效 ≠ 知道何时干预**——这是下一阶段问题。

**边界（诚实声明，不超卖）**：
- 我们识别的是"方向条件化披露策略"的因果效应，不是存在一个普适、客观正确的"证伪证据分类器"；
- 方向标签是模型自报的（未指定目标选项，攻击可能指向正确选项），不是客观语义真值；
- 披露的证据可能与讨论中的自然语言表达相同事实（部分效果可能是"重提/显著性"而非全新信息）；
- 效应是状态依赖的救援，不是普适增强器；对一开始就对的小样本（n = 2）不主张"无害"。

## 附录 A：错误现象、因素与可观测信号（技术索引）

### A.1 观测到的错误现象（P1–P6）

| # | 现象 | 证据 |
|---|---|---|
| P1 | **群体过早锁定错误答案** | 45 任务中第一轮就错得很严重的（round-1 Brier > 1.0）有 15 个；示例：task 14 群体第一轮即以 ~1.0 概率押错误选项 B（正确为 C） |
| P2 | **讨论强化错误而非纠正** | CONTROL 准确率 0.63；HiddenBench 协议下多 Agent 仅 23–30% |
| P3 | **关键证伪信息未进入公共视野** | "攻击"类证据被 supports-only 选择器静默丢弃；披露它们（披露量 5.49 vs 5.34，基本等量）产生 H1 = −0.412 |
| P4 | **方向干预在部分任务上翻车** | 7/45 任务 ATTACKS 失败：2 个真正反转（决定性线索是证实性的 / attacks 指向正确选项自身），5 个近零噪声 |
| P5 | **失败预测不迁移** | 开发集任务内 r = 0.388（总 r = 0.641）；确认集（2 runs/task，弱检验）r = −0.08 |
| P6 | **自报方向标签不可靠** | ≥1 个反转任务把正确选项的 trade-off 误标为攻击；GLM 系列跨模型观察显示同样模式（INFERENCE，探针级） |

### A.2 导致错误的四方面因素与可观测信号

**A. 信息结构（任务层面）**——hidden-profile 分布（每人只有部分事实）、biased sampling（讨论偏向共享信息）、决定性证据分散。可观测：每个 agent 的私有信息、round-1 证据条目（内容/标签/哈希）、`evidenceReuse`/`evidenceDiversity`——均 **Online truth-blind**（运行时可用，无需正确答案）。

**B. 认知与标签（模型层面）**——自报标签未定义"相对什么"（INFERENCE）、早期过度自信、跨模型标签漂移（探针级）。可观测：round-1 概率向量——**Online truth-blind**；标签金标准对照、Brier/severity——**Offline diagnostic**（需要正确答案，只能事后分析）。

**C. 群体动态（社会层面）**——从众修订、错误级联、锁定+强化循环。可观测：信念轨迹、一致性指标（alignment——**过程指标，不是决策质量**）、round-2 证据复用率——均 **Online truth-blind**。

**D. 治理设计（干预层面）**——披露方向选择、无真相盲路由、方向与数量混淆风险（全量披露无法归因）。可观测：**pre-treatment severity**（round-1 Brier，第一轮错得多严重）——**Offline diagnostic**（Brier 需要正确答案；虽是干预前协变量，但不是可在线使用的信号）；披露记录、披露后信念变化——**Online truth-blind**。

## 附录 B：干预体系与贡献分层

### B.1 系统组件按角色分类

| 角色 | 是什么（人话） | 当前状态 |
|---|---|---|
| **Observable / Diagnostic（观测与诊断）** | 我们能看见什么信号：运行时可用 vs 只能事后分析 | 全部已实现（见 A.2 标注） |
| **Router / Decision（路由决策）** | 决定"什么时候干预、干预谁、给什么证据"的模块 | **无已实现版本**：唯一测试过的候选（证据复用率）确认集未复现（0.388 → −0.08），无控制权限 |
| **Intervention（治理动作）** | 真正改变讨论过程的动作 | 方向条件化披露（已做，论文核心）；预算化分配（已提出） |
| **Outcome（离线评估）** | 怎么判断效果 | Brier / accuracy / LOTO / severity 分层（全部离线） |

### B.2 三层贡献

**别人已经知道什么（Existing literature）**：失败存在（Stasser & Titus / HiddenBench）、通信结构可变（Debate / CHAL）、从众与级联（Easier to Mislead / Spark to Fire）、一致 ≠ 正确（Emergent Consensus / CAGECAL）。——但"已产出证据的披露**方向**"未被隔离研究。

**我们已经证明了什么（SwarmAlpha established contributions）**：
- **identical-state fork**：同一第一轮状态分叉三组，结果差异归因于披露方向（FACT）；
- **direction-conditioned disclosure**：等量披露下方向本身因果改变决策质量（H1 −0.412 / H2 −0.330，LOTO 稳健，FACT）；
- **truth firewall**：在线披露不读正确答案（FACT，协议与代码）；
- **intervention–routing boundary**：干预有效但预测器不迁移——"干预效应 ≠ 已解决的路由"（FACT）；
- **state-dependent rescue（探索性）**：错得越严重收益越大（ρ = −0.60，事后分析）。

**我们下一步准备验证什么（Next-stage）**：
- **共识定向证伪披露**：只披露攻击群体当前首选答案的证据（truth-blind）——针对方向披露翻车机制（DESIGN INTENT，已写入论文 Future Work）；
- **标签保真度验证/校准**：自报方向标签的离线验证与校准（HYPOTHESIS）；
- **语义来源依赖**：预测有害收敛（HYPOTHESIS）；
- **跨基准复现**：方向效应在第二个基准/域是否成立（HYPOTHESIS；跨模型部分已由 GLM-4.6V 三执行作为 V2 复现证据解决，见下）。
