# M1 Pre-peer Source Audit

Date: 2026-08-28  
Status: **M1 EXECUTED + ANALYZED; ONE-STEP RESPONSE ONLY**

## FACT

The current dev10 formation directory contains the ten pre-existing task IDs
`1, 8, 15, 22, 29, 36, 43, 50, 57, 64`. Each stored formation has three
complete synchronous rounds, including round 1, and a complete round-1 roster.
The agent counts are:

```text
task:   1  8 15 22 29 36 43 50 57 64
agents: 4  3  4  4  4  4  4  3  4  4
```

The total is 38 task-agent views. A four-cell `NO_PEER_A/B` plus `PEER_A/B`
screen would therefore contain **152 calls**, not 160. This correction is made
before any M1 provider call.

Round 1 is a usable candidate pre-peer checkpoint: the public discussion
protocol is synchronous and agents do not see other round-1 messages when
producing their own message. The stored artifact nevertheless contains all
round-1 messages, so the M1 view adapter must explicitly construct two views:

- `NO_PEER`: public context, own private information, claim/options, own
  round-1 message, and no peer-message block;
- `PEER`: the identical fields plus all other round-1 messages in canonical
  roster order.

The existing post-R3 sensor snapshot builder includes peer messages by design.
It can be reused for field validation and prompt/parser components, but its
output must not simply be relabeled as `NO_PEER`. A dedicated pre-peer view
projection must hash the omitted peer block and the resulting prompt bytes.

The freeze contains 38 task-agent views and 152 cells. The authorized GLM

Here `R` is the peer-versus-no-peer response for a frozen task-agent view;
`G` is the A/B duplicate gap within one condition. At the task level, 7/10
tasks have mean `R` greater than both condition-specific duplicate means. The
response is heterogeneous: task 22 has mean `R=0.5125`, while task 29 has a
large PEER duplicate gap (`0.4392`). These are descriptive diagnostics, not a
significance claim or a dynamics result.

The contrast identifies a change associated with adding the frozen round-1
peer-message block relative to its no-peer re-elicitation control. It still
mixes peer content, added token mass, formatting and salience; it does not
identify social persuasion, latent belief, wrong-consensus formation,
recoverability, or a thermodynamic law. The M1 result supports only the claim
that a one-step peer-conditioned report response is measurable enough to
motivate a separately designed matched-sham or multi-round test.

## MATCHED-SHAM FOUNDATION (ZERO-PROVIDER)

Following the heterogeneous M1 response, a matched-sham freeze was prepared
without changing the original M1 artifact. It registers the same 38 frozen
task-agent views with six cells per view:

```text
NO_PEER_A/B
PEER_A/B
SHAM_A/B
```

The resulting denominator is 228 cells. SHAM preserves the number and order
of peer-shaped message slots and the character length of each source message,
but replaces source content and source agent identifiers with deterministic
neutral filler. It contains no source task facts, option labels or advice.
This is a formatting/length control, not a proof of semantic equivalence to
peer discussion and not a control for every salience or readability effect.
